# Cross-Dataset Generalization: IBM AML (HI-Small)

Evaluates how well the three detection agents — trained on SAML-D-style data — generalize to the IBM Transactions for
AML dataset, a second, independently generated synthetic world they have never seen.

## The dataset

**IBM Transactions for Anti-Money Laundering** (Kaggle: `ealtman2019/ibm-transactions-for-anti-money-laundering-aml`),
generated by AMLworld: an agent-based simulation of individuals, companies and banks transacting across currencies and
payment formats, with labelled laundering patterns injected (fan-in, fan-out, cycles, scatter-gather, bipartite,
stacks). Six variants exist (HI/LI illicit ratio x Small/Medium/Large); **only HI-Small is used here** (~5.1M
transactions, ~450MB) — the standard research configuration. The `patterns.txt` companion file lists every injected
laundering attempt with its constituent transactions, giving typology-level ground truth.

Reading list, in order:

1. Altman et al., *Realistic Synthetic Financial Transactions for Anti-Money Laundering Models*, NeurIPS 2023 Datasets &
   Benchmarks — the dataset paper.
2. Egressy et al., *Provably Powerful Graph Neural Networks for Directed Multigraphs*, AAAI 2024 — GNN baselines on this
   data; reference numbers for the network agent comparison.
3. Oztas et al., *SAML-D* — the dataset family the agents were trained on; needed to frame the cross-dataset claim.

Methodology notes reviewers care about: always split **temporally** (random splits leak on this data), and report
PR-AUC / minority-class F1 — never accuracy — because the illicit rate is far below 1%.

## Files

| Script                    | Purpose                                                                                              |
|---------------------------|------------------------------------------------------------------------------------------------------|
| `prepare_ibm_aml.py`      | Maps HI-Small onto each agent's feature schema; writes parquet + mapping-coverage stats              |
| `evaluate_zero_shot.py`   | Runs the *currently trained* TPA/CRA models unchanged on the mapped test window                      |
| `recalibrate.py`          | Best-F1 threshold search on the target domain (discrimination vs calibration decomposition)          |
| `retrain_on_ibm.py`       | Same TPA/CRA architectures retrained on the IBM train window; per-typology recall via `patterns.txt` |
| `prepare_naa_features.py` | Network agent's 11 graph features per temporal window (approximations documented in the script)      |
| `naa_experiments.py`      | Network agent zero-shot + retrained; account-level per-typology recall                               |

## Honest limitations of the mapping

- **Locations are a schema gap.** IBM identifies parties by bank code, not country; the transaction agent's two location
  features receive an unseen constant and one-hot to zeros (`handle_unknown='ignore'`). 36 of the model's 57 encoded
  inputs are therefore inert in this transfer.
- Currencies/payment formats the model never saw (Yuan, Ruble, Bitcoin, Reinvestment, ...) also encode to zeros;
  coverage rates are printed by the prepare script and belong in any reported results.
- `cross_border_ratio` and `unique_receiver_countries` are proxied with cross-bank equivalents; `amount_consistency`
  uses std/mean because the original training-time definition is not recoverable.
- **Centrality features are graph-size dependent.** The network agent was trained on graphs orders of magnitude smaller
  than IBM's ~500K-account graph, so zero-shot centrality values land far outside the deployed scaler's training range.
  This is a known transfer failure mode of non-normalised graph features and is measured, not patched.
- NAA betweenness/closeness/clustering are approximated (sampled pivots, landmarks, capped triangle counting — constants
  in `prepare_naa_features.py`); Louvain community ids are re-indexed by descending community size.

These gaps are part of the finding, not a flaw to hide: schema mismatch is a first-class failure mode of
cross-institution model transfer.

## Experiment ladder

1. **Zero-shot** (`evaluate_zero_shot.py`) — current models, unchanged, on the IBM test window. Measures
   out-of-distribution transfer.
2. **Retrain on IBM** — same architectures, IBM train window, evaluated on the IBM test window; per-typology recall
   using `patterns.txt`.
3. **Cross-dataset both ways** — train SAML-D -> test IBM and train IBM -> test SAML-D; the full generalization table.

Network-agent graph features (pagerank, centralities, communities over ~500K accounts) require approximation choices
(sampled betweenness, landmark closeness) — see `prepare_naa_features.py` + `naa_experiments.py`. NAA per-typology
recall is account-level (flagged account participated in the typology), so its typology *ranking* is comparable to TPA's
transaction-level numbers but the magnitudes are not.
